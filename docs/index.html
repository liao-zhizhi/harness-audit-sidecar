失败时，系统除了记下失败，还会写一份 161 字的事故报告（声称 / 见证 / 分叉 / 下次检查点）。 When it fails, the system records the failure and writes a 161-word post-mortem: claim, witness, divergence, and the next checkpoint.

从失败到规则：机器如何在事前避坑。 From Failure to Rule: The Learning Loop

失败 → 痛觉 Failure → Pain

物理失败由 Sidecar 捕获，写成多尺度痛觉事件，不是模型自述。 Physical failures are captured by Sidecar and written as multi-scale pain events, not model self-reports.

痛觉 → 叙事 → 人的修正 Pain → Narrative → Human Correction

痛觉被压成可读的事故报告。人读完后的修正记为带物理证据的校正记录。 Pain is compressed into a readable post-mortem. A human correction is stored with physical evidence.

修正 → 蒸馏预案 → 事前避开 Correction → Distilled Plan → Pre-action Avoidance

离线蒸馏把多条修正收成一条可复用预案。下次任务前先读取预案，检查之后再执行。 Offline distillation turns several corrections into one reusable plan. Before the next task the agent reads that plan and checks before acting.

实测：`fake_dir11` 任务中，它先调用 `get_recent_plans`，读到“写文件前检查父目录”的预案，先 `mkdir` 再写，一次通过，没有产生新的失败。 Verified: in the `fake_dir11` run, it called `get_recent_plans`, read the “check parent directory before write” plan, ran `mkdir` first, and passed on the first attempt with no new failure.

当前已验证的闭环只覆盖“缺父目录”这一种失败形态；权限、符号链接、多步级联的规则蒸馏尚未验证。规则读取仍是软约束，Sidecar 的物理阻断仍是最终防线。 The verified loop currently covers only the “missing parent directory” failure shape. Distillation for permission, symlink, and cascading failures is not yet verified. Plan reading remains a soft constraint; Sidecar’s physical block remains the final line of defense.

为什么纯 Prompt 救不了 Agent？ Why Prompting Isn't Enough?

模型无法内化契约 Models cannot internalize contracts

我们做了一个极端测试：移除所有外部规则和工具描述，看模型能否自己学会“在写文件前请求物理见证”。结论是：不能。模型依然会盲目直接执行。大模型可以被约束，但无法被“教会”内化契约。

We ran an extreme test: removing all external rules and tool descriptions to see if the model could learn to "request physical witnesses" before writing. The result: No. It still acts blindly. LLMs can be constrained, but they cannot be taught to internalize contracts.

规则套用是盲目的 Rule application is blind

模型分不清“缺少父目录”和“缺少写权限”。只要看到类似场景，它会把 A 场景的痛觉规则生搬硬套到 B 场景，导致依然失败。它缺乏对物理后果的推演能力。

The model cannot distinguish between "missing parent directory" and "missing write permission." It blindly applies rules from scenario A to scenario B, causing failure. It lacks the ability to deduce physical consequences.

唯一的防线在外部 The only defense is external

这就是为什么你需要 Sidecar。因为模型不可靠、规则容易套错、内化不存在，所以必须有一个独立的物理侧车，死死卡住它的每一个动作，用文件哈希和权限位做最后裁决。

This is why you need Sidecar. Because models are unreliable, rules get misapplied, and internalization doesn't exist, you must have an independent physical sidecar to hard-block every action, using file hashes and permission bits as the final verdict.

注：当前结论基于 `chmod 000` 和缺父目录场景的实测。对于更复杂的物理环境，Sidecar 的拦截判据需要相应扩展。 Note: Current conclusions are based on tests with `chmod 000` and missing parent directories. For more complex physical environments, Sidecar's blocking criteria will need to be extended.
